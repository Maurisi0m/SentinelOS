## CASO 1: Necesito modificar en un servidor Linux el archivo /etc/nginx/nginx.conf sin interfaz gráfica para cambiar el worker_processes de 1 a auto, verificar la sintaxis y recargar el servicio sin perder conexiones activas. Dame la secuencia de comandos segura.

Para modificar archivos críticos de configuración en el servidor sin interfaz gráfica, se debe aplicar un flujo atómico y defensivo:

```bash
# 1. Generar respaldo con marca de tiempo ISO-8601 antes de cualquier edición
sudo cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak.$(date +%F_%H%M%S)

# 2. Reemplazo seguro in-place mediante sed validando que coincida exactamente la directiva
sudo sed -i -E 's/^[[:space:]]*worker_processes[[:space:]]+[0-9]+;/worker_processes auto;/' /etc/nginx/nginx.conf

# 3. Verificación de sintaxis de la configuración (Dry-Run sintáctico)
sudo nginx -t
```

```bash
# 4. Si el código de retorno fue exitoso ($? == 0), aplicar recarga suave (Graceful Reload)
if [ $? -eq 0 ]; then
    sudo systemctl reload nginx
    echo "[OK] Configuración recargada sin interrumpir conexiones TCP activas."
else
    echo "[ERROR] Fallo de sintaxis detectado. Restaurando respaldo..." >&2
    sudo cp /etc/nginx/nginx.conf.bak.* /etc/nginx/nginx.conf
    exit 1
fi
```

Conceptos operativos:
- [[sed]]: Editor de flujo no interactivo. La bandera `-i` aplica cambios directamente sobre el inodo original, y `-E` habilita expresiones regulares extendidas.
- [[systemctl]]: El comando `reload` envía una señal [[SIGHUP]] al proceso maestro de Nginx, el cual levanta nuevos procesos trabajadores y cierra los antiguos una vez atienden las peticiones en curso.

## CASO 2: Tengo un disco casi lleno en /var/log. ¿Cómo encuentro los 10 archivos más pesados mayores a 100MB, comprimo los antiguos modificados hace más de 7 días y vacío los logs activos sin romper los descriptores de archivo de los demonios?

Para liberar almacenamiento en particiones saturadas sin provocar fallos en demonios en ejecución, nunca se debe ejecutar `rm` sobre un log activo, ya que el proceso retendrá el descriptor de archivo abierto ([[lsof]]) y el kernel mantendrá el espacio asignado en el sistema de archivos.

```bash
# 1. Localizar los 10 archivos más pesados en /var/log con tamaño legible
sudo find /var/log -type f -size +100M -exec du -h {} + | sort -hr | head -n 10

# 2. Comprimir de forma atómica los archivos de rotación antiguos (> 7 días) no comprimidos
sudo find /var/log -type f -name "*.log.[0-9]*" -mtime +7 ! -name "*.gz" -print0 | \
    xargs -0 -r -P 4 gzip -9

# 3. Vaciar archivos de log activos sin destruir el descriptor de archivo abierto
# Se utiliza truncado con redirección nula (> o truncate -s 0)
for logfile in /var/log/sentinel_service.log /var/log/syslog; do
    if [ -f "$logfile" ]; then
        sudo truncate -s 0 "$logfile"
        echo "[INFO] Archivo truncado a 0 bytes: $logfile"
    fi
done

# 4. Verificación del espacio liberado en el sistema de ficheros montado
df -h /var/log
```

Fundamentos:
- [[truncate]]: Modifica la longitud del fichero en el inodo a 0 bytes sin eliminar el enlace físico en la tabla del sistema de archivos, preservando la continuidad del flujo de escritura del demonio.
- [[xargs]]: Con `-print0` y `-0` maneja nombres de archivo con espacios o saltos de línea de forma inmune a inyecciones de shell, y `-P 4` paraleliza la compresión en 4 hilos de CPU.

## CASO 3: ¿Cómo generar un archivo de configuración multilínea complejo para Mosquitto MQTT en Linux usando bloques Heredoc con permisos restringidos?

Para escribir configuraciones completas desde la terminal evitando la interactividad de editores visuales, se utiliza un bloque [[Heredoc]] (`cat << 'EOF'`), citando el delimitador `'EOF'` para evitar la expansión prematura de variables de entorno de la shell:

```bash
# 1. Creación del directorio de configuración si no existe
sudo mkdir -p /etc/mosquitto/conf.d

# 2. Escritura atómica del archivo de configuración sin interpolación involuntaria
sudo tee /etc/mosquitto/conf.d/sentinel_mqtt.conf << 'EOF' > /dev/null
# Configuración de Broker MQTT para Laboratorio STEM
listener 1883 0.0.0.0
allow_anonymous false
password_file /etc/mosquitto/passwd

# Persistencia de mensajes en disco
persistence true
persistence_location /var/lib/mosquitto/
autosave_interval 1800

# Registro y auditoría
log_dest file /var/log/mosquitto/mosquitto.log
log_type error
log_type warning
log_type notice
log_type information
connection_messages true
log_timestamp true
EOF

# 3. Asignación de permisos restrictivos (Principio de Mínimo Privilegio)
sudo chown mosquitto:mosquitto /etc/mosquitto/conf.d/sentinel_mqtt.conf
sudo chmod 0640 /etc/mosquitto/conf.d/sentinel_mqtt.conf

# 4. Comprobar permisos aplicados en octal
stat -c "%a %U:%G %n" /etc/mosquitto/conf.d/sentinel_mqtt.conf
```

El permiso `0640` (`rw-r-----`) garantiza que únicamente el usuario propietario (`mosquitto`) puede leer y escribir, el grupo asignado puede leer, y otros usuarios del sistema tienen denegado el acceso al archivo.

## CASO 4: ¿Cómo sincronizar de forma incremental un directorio de modelos de 50GB entre dos servidores de laboratorio mediante rsync sobre SSH, garantizando integridad por checksums y excluyendo temporales?

Para transferir volúmenes masivos de modelos neuronales y pesos binarios entre hosts mediante la red local, se debe emplear [[rsync]] sobre un túnel seguro [[SSH]], aplicando algoritmos de cálculo diferencial de bloques y verificación criptográfica:

```bash
# Sincronización diferencial de producción:
rsync -avzP \
    --checksum \
    --partial-dir=.rsync-partial \
    --delete-after \
    --exclude='*.tmp' \
    --exclude='__pycache__/' \
    --exclude='.git/' \
    -e 'ssh -T -c aes128-gcm@openssh.com -o Compression=no' \
    /opt/sentinel/models/ \
    usuario@192.168.10.50:/opt/sentinel/models/
```

### Desglose de Parámetros Operativos:
- `-a` (*Archive*): Preserva recursividad, enlaces simbólicos, permisos, marcas de tiempo, propietario y grupo.
- `--checksum` (`-c`): Fuerza la comparación de archivos mediante hash MD5/SHA en lugar de fiarse del tamaño y fecha de modificación, garantizando que modelos con corrupción de bits silenciosa sean retransmitidos.
- `--partial-dir`: Si la conexión de red se interrumpe, almacena los fragmentos incompletos en un directorio temporal oculto para reanudar la transferencia exactamente desde el último byte recibido.
- `-e 'ssh -T -c aes128-gcm...'`: Selecciona el cifrado `aes128-gcm` asistido por hardware en CPUs modernas ([[AES-NI]]) y desactiva la compresión SSH (`Compression=no`), evitando saturar la CPU al transferir archivos binarios que ya están comprimidos o cuantizados.

## CASO 5: ¿Cómo inspeccionar y reemplazar una cadena de texto en 500 archivos de código fuente Python sin alterar los permisos originales ni las marcas de tiempo?

Para realizar una refactorización masiva de identificadores o rutas de importación en un árbol de directorios sin alterar los metadatos de inodo, se combina [[find]], [[grep]] y [[sed]]:

```bash
# 1. Pre-auditoría: Listar únicamente los archivos que contienen la cadena objetivo
grep -rnw --include="*.py" "/opt/laboratorio/src" -e "old_telemetry_endpoint"

# 2. Reemplazo seguro preservando permisos y atributos de inodo
find /opt/laboratorio/src -type f -name "*.py" -exec grep -l "old_telemetry_endpoint" {} + | \
    while IFS= read -r file; do
        # Preservar marca de tiempo de acceso y modificación con touch de referencia
        touch -r "$file" "${file}.time_ref"
        
        # Reemplazo in-place
        sed -i 's/old_telemetry_endpoint/sentinel_telemetry_v2/g' "$file"
        
        # Restaurar marcas de tiempo exactas previas a la edición
        touch -r "${file}.time_ref" "$file"
        rm -f "${file}.time_ref"
        echo "[ACTUALIZADO] $file"
    done

# 3. Verificación de integridad post-operación (debe devolver 0 coincidencias de la cadena antigua)
grep -rnw --include="*.py" "/opt/laboratorio/src" -e "old_telemetry_endpoint" || echo "[ÉXITO] Cero coincidencias residuales."
```

El uso de `grep -l` antes de invocar `sed` asegura que solo se toquen los archivos que efectivamente contienen la cadena, evitando operaciones de escritura innecesarias en el disco SSD.
